# Policy ownership and delivery

This module implements the six existing canonical operations: `listPolicys` (canonical spelling), `createPolicy`, `getPolicy`, `updatePolicy`, `commandPolicy`, `simulatePolicy`. Commands support DRAFT edit/regression/publication request, independent publication approval/rejection, and terminal clone. No arbitrary evaluator, extra route, live fixture ACTIVE policy, or client-authored regression report is accepted.

`PolicyConfig` validates the finite closed config. `PolicyEvaluator` applies the fixed fee/term/document/authority/SoD/reviewer/current-condition rules. `PolicyRegression` materializes all 20 authored POLICY-CORPUS-1 vectors and separately computes the documented expected outcomes, including equal pricing bounds, term subsets and out-of-wire boundary values. RUN_REGRESSION is product functionality; no application test or business HTTP scenario was executed for this delivery.

`PolicySchedule` owns the singleton persistent schedule counter, initial zero, one future reservation, range exclusion and atomic ACTIVE/RETIRED transition. The due reservation itself is durable database intent, retried by a transaction poller after crash; no new Job parent/kind is invented. Publication and activation lock the same publication/schedule rows before policies. First publication must start tomorrow or later in Asia/Ho_Chi_Minh. Before the first policy becomes ACTIVE, business resolution fails with POLICY_BLOCKED. Existing future slots and stale schedule counters fail with POLICY_SCHEDULE_CONFLICT. Interval closure, publication and worker activation/retirement are audited.

`PolicyAccess.requireApplicable()` joins the caller transaction, resolves overdue activation under the schedule lock, and returns the current real policy. `evaluateFrozen(policyId,facts,targetBranchId,sourceFactsHash,humanVerificationRequired)` retains the frozen published policy while checking current user role/branch eligibility. It rejects an unpublished policy or absent target branch. The source module must lock its real aggregate, load and validate current scoped bytes/evidence/checks, and build the internal facts projection; HTTP mock evidence is never business input. All cumulative source contributors are preserved (up to the source contract's 50); the simulation-only FactVector limit20 does not constrain internal business facts. The returned BLOCKED route must be enforced by the source owner with the applicable canonical error and no business mutation.

FACTS simulation has no target branch in the frozen wire DTO. It checks observable current active roles and SoD, but records TARGET_BRANCH_SCOPE=REVIEW_REQUIRED and presents only a hypothetical route. It never infers scope from policy-user grants or candidate IDs. Its factsHash covers exactly the seven NFC-normalized FactVector fields. REGRESSION uses synthetic authored candidate/scope context only inside its finite corpus. Simulation does not persist state, audit mutations, reports or jobs.

Compilation/package is performed with `mvnw.cmd '-Dmaven.test.skip=true' package`. Source review/build are not FE/browser, database-race, performance or integrated G3 acceptance. Approval rounds, frozen dossier revisions, artifacts, signing and agreement readiness belong to the next module tranche.
