# Reporting and scoped audit

Canonical A/B1.2.0 operations: `getDashboard`, `listAuditEvents`, `exportAuditCsv`. No schema, request, enum, permission or Frontend file changes. These operations become source-available under the existing approved contract; runtime/business acceptance remains separate.

Dashboard accepts only canonical `branchId`. A read-only PostgreSQL REPEATABLE_READ transaction uses one `asOf`, seven dossier-state counts and the nine predicates in A§12.2. Recorded ACTIVE is distinct from observed service. Review overdue requires the current OPEN round bound by its target's `roundId`; historical breaches count distinct scoped obligations with actual immutable breach records recorded by asOf, including closed/cancelled duties. Expiring30 uses current immutable terms and Vietnam calendar dates. Lag uses the shared current-parent-scoped EFFECTIVITY read port at the same asOf. No timeline writes or fabricated future-domain data are performed.

Business read roles are MAKER/CHECKER/MANAGER/DATA_OFFICER/AUDITOR with current explicit branches; a maker additionally needs the current assigned Relationship reached through source ancestry. Admin/policy-only actors do not gain business metrics. Empty business branch scope is forbidden, never an invalid empty Dashboard.branchIds response.

Audit filters use actual `occurred_at` with inclusive createdFrom/exclusive createdTo, exact resource/actor/action filters, and occurred_at DESC/id DESC order. Stored CamelCase resource types are mapped to the canonical UPPER_SNAKE enum without rewriting immutable history. Scope is resolved through current real resource/parent ancestry before query/paging/export, including own deleted staging uploads only while their real parent remains currently authorized. Null-branch admin and Policy namespaces are separately purpose bounded. CSV export provenance has its own narrow actor/branch rule; no generic orphan-row access. User-authored reason text is redacted; no raw contacts, payloads or secrets are returned.

The reporting-owned HMAC cursor uses the existing cursor secret, operation/order/actor/roles/branches/permissions/filters, first-page anchor, last key and original 15-minute expiry. Current source/assignment scope is still applied on every page; paging does not promise a frozen dataset. Changing filters/grants invalidates the cursor fingerprint.

CSV uses exactly the nine B§5 columns, UTF-8 BOM, CRLF, RFC4180 quotes and apostrophe defense for formula prefixes after whitespace. Supplemental EXPORT and normal scope are required. SQL fetches at most 1001 rows; exceeding 1000 returns EXPORT_LIMIT before returning bytes or recording a successful export. Bounded source selection and safe export audit writes share a normal (not read-only) REPEATABLE_READ transaction. Export reasons remain redacted regardless of SENSITIVE_READ. No migration is needed; owned domain tables are read only and only the existing AuditService writes audit provenance.
