# Dossier approval tranche

Authorities: A1.2.0 §§3.1,5.1–5.3 and B1.2.0 §§4,6–7, exact Revision/Round/EvidenceCheck/MandatoryCheck schemas and seed hashConventions. This implementation has four canonical Round handlers for DOSSIER only. CHANGE and CONTROL_REQUEST have no adapter yet. They are explicitly partial operations, not an invented generic approval engine.

Dossier SUBMIT joins the existing CommandExecutor transaction and dossier lock, resolves/locks current confirmed Relationship contact and Party, validates tomorrow-or-later Vietnam start, current real scoped CLEAN evidence and private byte identity, current reviewers/SoD/sensitive grants, published policy and supplied current conditions. It freezes the closed Revision separately from cg_entity. Internal immutable metadata retains party identity, contactVersion, exact ordered document references via Revision, purpose/file/byte digests, template/bundle and config hash. Facts/evidence hashes follow B's projections. All actual file associations become historical. The current revision embedded in Dossier is a convenience; historic Round snapshot always resolves its own immutable revision row. Auditor projections redact nested Revision contact/representation as well as current draft fields.

Action projections use PolicyAccess.findApplicableHint(), a plain read of published applicability intervals and immutable config, including a due SCHEDULED publication. It performs no activation, SELECT FOR UPDATE or transactional proxy call. Missing availability becomes an advisory blocker without poisoning a surrounding draft save transaction. Only actual SUBMIT calls the locking/materializing requireApplicable(). Thus read-only list pagination remains read-only and an empty policy schedule does not prevent creating/editing drafts.

Mutating Round commands resolve source then lock Dossier → Relationship → Round, recheck binding and current actor authorization before idempotency replay and new effects, check ETag, and lock File IDs in UUID order when checking evidence. Submission holds Dossier before Relationship; no Round exists until source/evidence is frozen. Withdrawal holds Dossier then its current Round. All paths serialize on their real dossier, retain approved step history, and never reopen a closed round. V006 provides immutable source/history tables, unique step decisions and Round binding/closed-history guards; V003's one-live-dossier-round index remains authoritative. Reassignment records old/new/actor/reason without changing dueAt or prior decisions. All histories/audit/domain changes join one transaction.

VERIFY_EVIDENCE is assigned independent current L1 only and requires its step still PENDING. It records a separate immutable assessment, never changes source facts or contributor IDs. Every referenced check and condition evidence ID must belong to the frozen source; duplicate codes/IDs and future timestamps are rejected. Known condition codes cannot disappear from later assessments or resubmission. B allows evidenceFileIds=[] and min1 mandatory code; the implementation does not invent an unconditional three-code rule or a stricter evidence-array minimum. Supplied BLOCK/REVIEW_REQUIRED conditions block policy evaluation; absent conditions are not materialized as PASS records. Current authority interval/revocation, source identity, file integrity, eligibility and SoD are checked independently of these client-authored condition labels.

RETURN/REJECT and WITHDRAW carry the round's latest mandatory condition set into mutable Dossier.mandatoryChecks before closing the round. A later SUBMIT therefore retains reviewer-discovered applicability as well as the original set; omission cannot erase a newly recorded legal/readiness blocker. Historic Revision and round assessment rows remain untouched.

For authority, the internal current-policy input first clears maker-supplied checkedAt/checkEvidenceFileId. Only an actual PASS check for the exact frozen representation source plus authorityChecked=true overlays its assessment checkedAt/source evidence. The latest assessment must come from the currently assigned eligible L1. Frozen Revision/hash remains unchanged. Required evidence is checked by a human separately from scanner CLEAN; real current policy evaluation retains the submitted published policy and all cumulative contributors. Re-evaluations have separate immutable rows; they never overwrite submitted Evaluation.

L1 approval promotes waiting L2. RETURN/REJECT close source/round and cancel undecided steps; WITHDRAW returns source to DRAFT while preserving the old revision/round and approved steps. Last APPROVE requires an actual OriginalAgreementPort bean. This tranche intentionally supplies none: SERVICE_UNAVAILABLE rolls back the entire effect, including step decision/evaluation/audit. No fake PREPARED contract, artifact or successful PDF job is created. The next contract owner must implement prepare(lockedDossier, RevisionStore.Frozen, approvedRound, actor) in the same transaction, persist its real immutable source/artifact intent, and return a correctly bound PREPARED Contract. Its richer typed source envelope prevents rendering from current mutable customer data.

Source compilation/package only, with test resources/compilation/execution skipped. No tests, HTTP scenarios or isolated runtime/database operations were performed. Independent source review and primary Flyway/runtime verification follow separately; this is not integrated G3 acceptance.
