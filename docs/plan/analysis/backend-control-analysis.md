## All five kinds and outcomes

- ACTIVATE: current assigned MAKER creates DRAFT; SUBMIT requires L1 CHECKER and L2 null, IN_REVIEW; complete reviewed Round yields APPROVED only. Separate independent CHECKER CONFIRM requires Contract ACTIVE, readiness READY, Service NOT_STARTED, acknowledgement not before operative agreement start and no future source timestamps. Only that confirmation changes service RUNNING. Never first-activate the legal Contract using service ACTIVATE.
- SUSPEND: assigned MAKER or scoped CHECKER urgent source, DRAFT→SUBMIT REQUESTED with both reviewers null. Do not require formal Round. CONFIRM by another independent CHECKER requires Contract ACTIVE and service RUNNING; source reason/evidence plus actual acknowledgement yields SUSPENDED. No inferred guilt/fraud or execution before confirmation.
- RESUME: MAKER DRAFT, L1-only Round IN_REVIEW→APPROVED. Separate CONFIRM requires ACTIVE, READY, observed SUSPENDED, no blockingResume Incident except RESOLVED/CLOSED, acknowledgement not before last confirmed SUSPEND acknowledgement. RUNNING only after source confirmation. Do not compare only createdAt or request approvalAt to last suspension.
- TERMINATE: MAKER DRAFT, L1 CHECKER + different L2 MANAGER; sequential L1_L2 yields APPROVED. CONFIRM independent CHECKER after timeline advance requires still ACTIVE, effectOn<=todayLocal, reviewed ground and applicable notice proof, actual stop acknowledgement or independently assessed neverStarted proof. One transaction: exact confirmed source, Contract TERMINATED, service STOPPED, authoritative current version interval closure, cancel other pending controls/Rounds and unapplied inapplicable Changes/jobs/slot, preserve all incidents/remediation/applicable obligations, create one CLOSEOUT. Keep effectOn, external observedAt and server recordedAt distinct; do not claim retroactive legal certainty.
- STOP: existing LifecycleControls creates SYSTEM REQUESTED on actual expiry when RUNNING/SUSPENDED (requesterId null,contributors[]). Manual MAKER DRAFT→REQUESTED, reviewers null, only EXPIRED/TERMINATED with observed nonstopped service. Independent CHECKER actual confirmation yields STOPPED, retaining EXPIRED/TERMINATED; no legal termination conversion. NOT_STARTED is not proof of never-started, and terminal observed STOPPED is not another stop to execute.

L1 can both approve and later confirm ACTIVATE/RESUME if still independent/current eligible; preserve two separate assessment events. Do not demand an invented third role/reviewer. L2 never approves before L1. Approval must require each source evidence PASS and appropriate authority/current mandatory guards; CLEAN is only malware status. Keep any reviewed required conditions when reassessing, and preserve previous assessments.
