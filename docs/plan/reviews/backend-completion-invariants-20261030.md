## Extended C02/C03 review — JOB-FENCE-01, P1 blocking

**Location:** `shared/JobQueue.java:25–41`, `files/FileScanWorker.java:21–34`. **Rules:** A BR-053, A§13.1/13.2 recovery consistency; B§7 lease/retry/durable effect and B§8 crash/lease oracle.

`claimForKind` writes the supplied worker UUID as `lease_owner` and returns that same UUID in Job. `renew`, `finish` and `fail` check only job ID, RUNNING, owner and unexpired lease. FileScanWorker has one fixed worker UUID and two concurrent execution slots. Therefore owner is not a claim-generation fence.

Source-derived interleaving (not executed):

1. Scan attempt A claims with worker token W; its task remains alive while the60s lease expires (for example scheduler/IO/DB stall).
2. Polling requeues expired A and claims attempt B in the other slot, again with W, before A returns. File version/hash/state remain the expected SCANNING source.
3. A resumes and passes its ordinary source/authority guard. A's `queue.succeed`, `queue.fail` or delayed heartbeat `queue.renew` now matches B's current RUNNING lease because owner W is reused. A can complete/fail/renew a lease it no longer owns; failure also uses A's older attempts/backoff value.

Normal scanner socket deadlines reduce typical task duration but do not establish claim identity under process/thread/DB stalls. A source guard on unchanged bytes does not substitute lease fencing. This review does not assert a reproduced corruption or a particular scanner result; it establishes that stale completion is permitted by the predicates.

**Minimal recommendation:** generate a new unpredictable UUID for every successful claim inside JobQueue.claimForKind, persist it as `lease_owner` and return precisely that token in Job. Preserve all renew/finish/fail owner+live predicates. A claim-token is independent of persistent worker identity and remains unique across reclaim and manual retry. Adding attempts alone is insufficient because manual retry resets attempts to0 (ABA). No schema, migration, canonical response, role or owner product decision is required.

All Java `leaseOwner()`/`lease_owner` consumers were searched. The returned token is used by queue predicates and `PrivacyJobs.lease`; no business caller compares it with a stable worker ID or exports it in the canonical Job. Source cancellation paths clear owner/expiry. The single-slot Privacy worker's extra attempts predicate is compatible with a unique token. Other current claimants already supply random UUIDs per poll, but fixing queue issuance centrally protects every claimant.

This finding reopens the **source implementation correctness** of durable infrastructure;85-route inventory coverage remains unchanged. Requires developer repair and independent review of exact diff. Race/fault-injection proof remains deferred, not silently run under source review.
