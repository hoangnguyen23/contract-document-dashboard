## Submission, immutable history and round decisions

Existing `DossierApprovalBridge.submit(Entity, JsonNode, Actor)` / `withdraw(Entity, String, Actor)` run inside DossierService's CommandExecutor transaction and locked dossier. Keep authorization-only scope checks before cached replay; apply state/ETag checks to a new effect. Finalize and document one consistent lock order across submit, round decisions, withdrawal and contract creation; round handlers first resolve the target, then acquire the same target-before-round order and verify the binding again.

SUBMIT body is exactly `action,mandatoryChecks,l1ReviewerId,l2ReviewerId`; l2ReviewerId is present and nullable. DRAFT/RETURNED only, current assigned active MAKER, tomorrow-or-later local start date, valid terms/authority source, current scoped CLEAN evidence and applicable policy are required. Build evidence flags from actual files, not simulation flags or fixture results. L1 route requires null L2; L1_L2 requires a different eligible scoped MANAGER. Both reviewers exclude every cumulative contributor/requester by stable ID; sensitive evidence additionally needs an eligible reader with SENSITIVE_READ. No role grant, reassignment or resubmit clears contributors.

Persist immutable Revision with exactly: `id,number,terms,representation,contact,documents,contributorIds,factsHash,evidenceHash,evaluation,submittedAt,externalAccountReference`. SubmittedRepresentation requires nonnull sourceFileId; checkedAt/checkEvidenceFileId remain nullable in the schema and cannot be replaced with fabricated PASS evidence. Resolve the authoritative confirmed contact/source version under the snapshot transaction; never use pending contact. Internal source metadata must also bind templateVersion=BASE-VA-1, bundleVersion=TERMS-VA-1, contact provenance and byte digests without adding those properties to the closed Revision response.

Hash NFC-normalized dossier projection `{terms,representation,contact,externalAccountReference,templateVersion,bundleVersion}`; hash evidence as `{fileId,purpose,sha256}` sorted by purpose then fileId. Preserve the authored document order in Revision. Record every revision independently and mark its file associations historical; V003 prevents later removal/demotion of historical references. Resubmission increments revision number, chooses current policy and creates a new round. GET `/rounds/{id}/snapshot` resolves by that round's revisionId and returns the exact discriminator envelope `{targetKind:"DOSSIER",revision:Revision}`, including after RETURN, withdrawal or resubmission. CHANGE and CONTROL_REQUEST use their own canonical snapshot schemas; unsupported targets fail closed until their genuine adapters exist.

Round has canonical `id,version,createdAt,updatedAt,allowedActions,branchId,targetKind,targetId,revisionId,state,policyVersionId,dueAt,steps,evidenceChecks,authorityChecked,mandatoryChecks,blockedActions`. OPEN starts L1 PENDING, optional L2 WAITING. No auto-reject/approve after this internal SLA.

## Original PDF, signing and readiness

Final approval creates one PREPARED Contract per dossier: approvedRevisionId and approvedTerms identify the exact approved source; currentVersion=null, scheduleVersion=1, scheduledChangeId=null, serviceState=NOT_STARTED, readiness=PENDING. Artifact/signing/readiness/effective/recorded/termination nullable fields are explicitly null; readinessRisks starts empty. Do not introduce approvedSnapshotId on the wire: B's approvedRevisionId is authoritative. Freeze source template/bundle and the artifact job intent in this same transaction. PDF failure retains this contract and exposes a retryable real job, never another contract.

ARTIFACT_PDF must render actual bytes from the frozen source/template, not today's customer/policy/dossier. Use `PrivateBlobStore.writePending`, retain its guard on the creating worker thread through the DB reference transaction, then close it on commit/rollback. A generated-file adapter must register private blob/file/association metadata and actual SHA-256, rendererVersion/generatedAt, origin=GENERATED and uploadedBy=null; scanner/integrity outcome is authoritative and humanVerification is not fabricated PASS. Completion rechecks immutable source hash/version, current cancellation state and job lease, then commits artifact bindings and job success atomically. Keep external PDF/scanner work outside long domain transactions; actual business dedupe keys and unique source association prevent duplicate effects after lease recovery. Existing FILE_SCAN dispatch and JobService retry/access require a real ARTIFACT_PDF source adapter before this path is operational.

SigningPacketCreate is exactly `targetKind,targetId,artifactId,artifactHash,signedCopyIds,signingMethod,authority,bankSignedAt,beneficiarySignedAt`. CONTRACT/CHANGE target, PAPER_SCAN/EXTERNALLY_SIGNED method, unique CLEAN signed copies staged on that target, exact approved artifact bytes/hash and both parties' authority are required. authority contains bank and beneficiary SubmittedRepresentation. Store immutable source inputs and cumulative contributorIds; PENDING packet has nullable verificationReason/verifiedBy/verifiedAt. Corrections create another packet, never PUT or edits to signed history.

VERIFY_SIGNING body adds checks,mandatoryChecks,reason; RETURN_SIGNING has reason. Independent scoped CHECKER excludes both source and signing contributors, verifies artifact/copy correspondence and authority at each reported signing instant, then writes separate assessment. Both signing times are ≤ server now; validFrom inclusive/validTo exclusive Vietnam dates and knownRevocationAt apply to each signing instant. Current mandatory/service-readiness evidence and unresolved risks must pass. ReadinessVerifiedAt is server time strictly before startOn local midnight; a late original verification is 422 LATE_SIGNING even if reported signatures predate the boundary. Missing evidence remains PENDING or blocked, never READY by default.

Valid on-time readiness changes PREPARED→SCHEDULED and creates durable EFFECTIVITY intent. HOLD_READINESS requires checker reason/evidence and may be raised by a contributor. RELEASE_READINESS requires another noncontributor checker, exact riskId/basis/evidence and current guard review; it cannot bless changed material identity/account/representation. CANCEL is only before first ACTIVE: unsigned assigned-maker reason; signed candidate requires independent checker and cancellation evidence. Contract and dossier become CANCELLED atomically; historical rounds/files remain.
