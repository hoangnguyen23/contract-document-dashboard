# Original signing and lifecycle tranche

Derived implementation record, 17 October 2026, canonical A/B 1.2.0. This adds one bounded original CONTRACT adapter; it is not whole-G3 acceptance. The upstream prerequisite source audit is `reviews/backend-g3-prerequisite-source-review.md`.

## Source behavior

- Four signing packet operations accept/serve CONTRACT sources. CHANGE is explicitly partial and returns SERVICE_UNAVAILABLE where its adapter is needed. Inputs are immutable; correction creates a new packet. Independent assessments are separate append-only records. RETURN does not rewrite reported inputs or fabricate verification.
- Each packet binds the exact approved artifact metadata, private bytes, immutable artifact association and input hash. Signed copies must be uploaded CLEAN files on that CONTRACT. Authority evidence may additionally use only files frozen into its own DOSSIER Revision; no unrelated relationship/dossier evidence is admitted. All used contract-file associations are retained historically.
- Actual packet submitters and contract evidence uploaders join a cumulative internal contributor ledger; original contributors/requester are always excluded as well. No contributor field is added to the closed Contract response. Human assessment itself does not add a contributor.
- VERIFY_SIGNING uses an independent current scoped CHECKER, current material source, per-party [validFrom,validTo)/knownRevocation at each reported signedAt, immutable byte manifests, nonfuture human assessments, retained applicable mandatory codes and actual SERVICE_READINESS confirmation evidence. Authority PASS references both parties' source/check files. Signed-copy PASS is the human correspondence assessment against the exact artifact; a generated CLEAN file alone never supplies that assessment. No free-text legal-rule parser, invented external boolean or unconditional optional LEGAL_CONDITION is introduced.
- Beneficiary material representation matches the approved source apart from assessment metadata; a changed signing scope cannot be approved using a maker checkedAt. Today's expiry of a previously valid authority does not itself invalidate a signature made inside its interval.
- On-time server readiness is strictly before the original local start boundary, sampled again after guard work. Valid verification changes PREPARED to SCHEDULED and creates genuine durable EFFECTIVITY intents available at start/end boundaries, not immediately claimable future jobs.
- Contract commands implement HOLD_READINESS, RELEASE_READINESS and pre-first-ACTIVE CANCEL. Risk raising can be by a contributor; release needs a different noncontributor checker and cannot legalize changed material facts. Signed candidate cancellation needs independent checker plus actual evidence; unsigned cancellation belongs to the current assigned maker. Dossier cancellation and job cancellation are atomic, preserving all history.
- One timeline authority serves detail/signing maintenance and workers. Maintenance uses a separate committed transaction only after an authorized idempotency cache miss and before a new command's ETag check. The original key advisory arbitration stays held across this hook, without holding outer domain rows. Cached replay returns without new timeline effects. Existing contract mutations lock Dossier -> Contract -> Relationship -> Party -> File before contribution/job records. File upload already owns Contract before appending contribution, never the reverse. Existing final approval locks Dossier/Relationship/Party/Round before creating a new Contract, so it cannot contend for an existing Contract in reverse order.
- First ACTIVE creates exactly one immutable ORIGINAL ContractVersion and effect event with actual boundary effectiveAt / actual recordedAt, completes the dossier and leaves observed service NOT_STARTED. FIXED activation creates a real deduplicated TERM_REVIEW entity. Fixed expiry creates a real CLOSEOUT and, only for observed RUNNING/SUSPENDED, an actual SYSTEM STOP REQUESTED with requester=null/contributors=[] and original-artifact provenance. No acknowledgement, task closure, STOPPED service or external execution is fabricated.
- Live ORIGINAL version effectiveTo remains null; contractual endExclusive stays in immutable terms. At expiry a separate append-only interval-closure record projects effectiveTo consistently in currentVersion and version listing. Original signing/activation/expiry do not advance the future-Change scheduleVersion counter. Catch-up activation and expiry effects share one transaction; required consequence failure rolls them all back.
- Any scheduledChangeId or actual READY/SCHEDULED Change requiring G4 prevents success while no renewal/apply adapter exists. Draft/unapproved proposals do not extend the original agreement. OPEN_ENDED never expires; terminal originals never revive.
- EFFECTIVITY jobs use a unique lease token per claim, immutable packet/source/boundary payloads, conditional lease completion and bounded retries; current guards are rechecked before effect. Guard/dependency failures use the closed Job error enum GUARD_BLOCKED; actual storage-integrity failures retain STORAGE_INTEGRITY. Current readiness-evidence failure materializes REVIEW_REQUIRED rather than returning an apparent READY candidate. Human review can record HOLD/RELEASE with real evidence after a recoverable source problem is repaired; altered material facts still require a new dossier. Existing Job APIs expose real retry for failed original intents. Successful detail maintenance is idempotent; subsequent worker completion cannot duplicate versions/tasks/effects.

Canonical schema, fields, enums and request shapes are unchanged. No breaking change and no contract/product patch was made; implementation follows the existing owner-approved baseline. Owner has authorized this backend continuation, not business/runtime acceptance.
